# One complete family in the managed batch workflow

The existing managed workflow accepts one to eight distinct complete family
preparations from the same verified schedule batch, in manifest order. One family
can run alone when an unrelated companion would exceed model context capacity.
This changes only the minimum batch count: it does not create a cross-batch
selector or change the schedule, family ownership, required dispositions, source
evidence, or supplied context.

Use the existing `batch-workflow-init` command with one preparation directory.
Primary research, selective independent verification, conditional blind escalation
and adjudication, exact independent release review, accounting, and explicit
publication/closure all remain required. A single family does not authorize a
single-call acceptance shortcut. No model call or accepted market is implied by
successful preparation or a synthetic test.

Freeze the reviewed runtime and regenerate the complete preparation, workflow,
request measurement, and explicit authorization before execution. Measure actual
wire admission and model context fit including any supplemental evidence and
navigation; a family count alone does not establish fit. Existing historical runs
retain their original frozen runtimes and receipts. Empty, oversized, duplicate,
mixed-batch, partial, stale, or tampered scopes remain invalid.

The original two-to-eight-family behavior remains available. See the
[controller guide](batch-controller.md) for execution and stop states and
[issue #92](https://github.com/michaelsena/turbo/issues/92) for the context-capacity
motivation.
