# ADR 0018: Bounded expansion controls

Status: implemented as explicit operator controls; broader model and workload
qualification remains required before rollout.

The five-market publication proves one compact batch. Medium preparation showed
that counts of required or contextual identities are insufficient predictors of
request size. Readable deduplication materially reduced the accepted reviewer's
assignment bytes but barely reduced the medium primary. Neither result proves
model comprehension, token savings or full-universe affordability.

Retain the existing selective workflow and plain requests by default. A fresh
explicit authority may opt only the release reviewer into readable backward
references, binding both representation policy and implementation. Canonical
assignments, output schema, exact preview approval and evidence validation remain
unchanged. Historical/recovery authorities cannot silently adopt the new view.

A serial controller orchestrates existing role APIs with fixed attempt identities,
one authority and durable stop/wait states. It does not manufacture semantic release
choices. The GM supplies the explicit release configuration; a separate exact
independent review remains mandatory. Publication stays on the existing reviewed
operator path, with no implicit pointer mutation or stale-base rebase.

The workload report overlays supported, validated published activation closures on
the immutable schedule and separates completed disposition work from unresolved
gaps. Unsupported closure types fail closed. Time and cost scenarios require named
assumptions; unknown strata must not inherit compact-case economics silently.

These controls authorize no paid calls, new model defaults, blanket retries,
concurrent graph publication, ranking or app work. General recovery and arbitrary
parallel rebasing remain separate scopes.
