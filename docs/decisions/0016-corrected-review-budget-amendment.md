# ADR 0016: Explicit corrected-review aggregate amendment

Status: implemented for review under issue #57; no corrected production review
has been dispatched.

The original release reviewer and its single approved replacement returned HTTP400.
Two separately logged compatibility probes then isolated a Google-facing array-bound
problem. The second probe reached the model, but was not an accepted research result.
The original allowance is exhausted. A further call requires a new explicit aggregate
approval, not another use of the old single-successor claim.

Add one narrow corrected-review checkpoint for this pinned chain: the original
accepted primary/verifier and failed release, its already-claimed failed successor,
and both diagnostic journals. Reprove the original upstream provider artifacts and
exact attempted preview. Validate the first successor against its released execution
contract and the diagnostic sidecars against their preceding journal tips, calls and
exposure. Reject undeclared authorities in the registry.

The proposed authority names a new aggregate call/cost ceiling. Subtract all four
journals' committed charges and outstanding reservations; permit exactly one further
physical call and one exact replacement attempt ID. Preserve role assignments and
routing. Pin the corrected provider implementation and a unique append-only claim.
The canonical schema and accepted research are unchanged. This is not automatic retry,
a generic historical migration, retrospective approval, or permission to lower an
unknown charge to zero.

The original clean compiler commit still owns activation of the same preview. The
corrected reviewer must approve that exact preview before cumulative replay, closure
and publication. Existing HTTP402 and first HTTP400 procedures remain unchanged.
