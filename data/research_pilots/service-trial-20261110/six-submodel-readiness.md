# Six-submodel execution readiness

The approved trial rubric applies across six distinct submodels. Each has its own
two factors; all six use the same governed evaluation protocol. The code/policy
audit at `bbb390b4881b47ff83c8a032881f22624d20fbd1` verified six policy hashes,
twelve factors, sixty scoring anchors and all configured factor/task model mappings.

| Submodel | Factors |
| --- | --- |
| Demand and market attractiveness | Durable demand; competitive opening |
| LMM buyability and roll-up potential | Acquisition pricing; target availability |
| Base-business quality and cash economics | Quality of earnings; displacement resilience |
| Operating scalability and integration | Implementation feasibility; reuse across acquisitions |
| Ambient-AI workflow transformability | Increase in completed work; accumulated-context dependence |
| Ownership value capture and risk | Distinctiveness; retained economic value |

Factors have equal weight within their submodel, with 0/25/50/75/100 anchors and
a ten-point disagreement tolerance. Each submodel uses separate blind evaluator
calls, conditional adjudication and scoped comparison. The registered task policy
uses Terra/high for evaluator A and adjudication, and Gemini Argon/high for
evaluator B and comparison. These are configured policies, not a live endpoint
availability assertion. Comparison changes are bounded to five points; a
single-market cohort cannot invent a pairwise comparison effect.

The single-submodel execution and replay system is implemented and its twelve
synthetic execution tests passed. Actual execution remains blocked until accepted
eligibility exists and each factor workunit has frozen evidence, validated request
bounds, current routes/prices and separately bound authority. The six-submodel
call envelope is eighteen to twenty-four calls, plus eligibility separately.

Automatic six-unit orchestration, a shared spending pool and global aggregation
are not implemented. Global weights remain unapproved; this audit creates no
ranking or accepted scores. It does not replace real output-quality review.

The [machine-readable audit](six-submodel-readiness.json) preserves source and
policy hashes, exact anchors, task mappings and the remaining preparation steps.
